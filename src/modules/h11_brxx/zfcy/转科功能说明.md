# 转科功能实现说明

## 概述
基于旧HIS系统PowerBuilder代码实现的转科功能,实现病人在不同科室之间的转科申请。

## 接口信息

### 接口地址
`POST /h11_brxx/transferDepartment`

### 请求参数

```typescript
{
  zyid: string;           // 住院ID (必填)
  zkksid: string;         // 转科科室ID (必填)
  zksj: Date | string;    // 转科时间 (必填)
  ksid: string;           // 当前科室ID (必填)
  userid: string;         // 操作人ID (必填)
  gfbh?: string;          // 工费编号(养老使用) (可选)
}
```

### 返回结果

```typescript
{
  code: 0,                    // 0表示成功
  msg: string,                // 提示信息
  hasUnpaidFees: boolean      // 是否有未结账费用
}
```

## 业务流程

### 1. 前置校验
- 检查转科科室ID是否存在
- 获取病人基本信息

### 2. 药品和项目校验(可配置)

#### 2.1 未发药检查(根据参数zxyptx)
如果系统参数"zxyptx"(执行药品提醒)设置为'1',则检查以下内容:

**检查h13_yzzxcs表(医嘱执行次数表)**
- 条件: 未发药(fybz<>1)
- 药品类型: xmzl=2或3(西药/中药)
- 有未执行次数: (zxcs-bzxcs)>0
- 计费用量>0
- 科室范围: 西药、草药、中药、材料、其他、制剂科室

**检查h13_yzzxcs_tf表(医嘱执行次数退费表)**
- 同上条件,检查退费药品是否已发药

**检查h15_ssxb表(手术明细表)**
- 手术药品未发药
- 条件: 未退品(tpbz=0)、已提交(tjbz=1)
- 药品类型: xmzl=2或3
- 科室范围: 包含手术材料、精品、护理科室

如果发现未发药,抛出错误: **ERR_41005**

#### 2.2 未执行项目检查(根据参数zxxmtx)
如果系统参数"zxxmtx"(执行项目提醒)设置为'1',则检查:

**检查h13_yzzxcs表**
- 条件: 未收费(sfbz<>1)或未处理(clbz<>1)
- 项目类型: xmzl=1(非药品项目)
- 有未执行次数: (zxcs-bzxcs)>0
- 计费用量<>0且项目单价>0
- 费用类别: 护理、病床、西药、其他、中药、麻醉、CT、心电等

如果发现未执行项目,抛出错误: **ERR_41006**

### 3. 床位处理
- 检查病人是否有床位未停止
- 自动停止病人当前床位(清空h11_brxx的rycw、cycw、cybs字段)
- 清空h13_cwsyxx表中的zyid和cwfpxx字段

### 3. 费用结账检查
- 统计病人是否有未结账费用(h13_yzzxcs表中jsbz=0且sfbz=1的记录)
- 返回hasUnpaidFees标识,前端可根据此标识提示用户

### 4. 更新病人状态
- 将h11_brxx表中的zyzt字段设置为6(转科状态)
- 条件: cyksid匹配且zyzt < 3

### 5. 记录转科信息
- 向h13_brzkqk表插入转科记录
- 包含: 转科科室ID、转科时间、住院ID、录入时间、录入人ID、当前科室ID
- 等待目标科室确认

### 6. 转移押金(可配置)
- 根据系统参数"yjkzk"(转科同时转押金)判断
- 如果参数值为'1',更新h11_yjk表的ksid为转科科室ID

### 7. 医嘱数据处理(可配置)
- 根据系统参数"zkjl"(转科前与转科后分开)判断

#### zkjl = '1' (直接更新到新科室)
更新以下表的科室ID:
- h12_yzzb (医嘱主表)
- h12_yzxb (医嘱明细表,同时设置qt1='1')
- h13_yzzxcs (医嘱执行次数表)
- h11_yjk (押金表)
- h12_blzb (病理主表)
- h15_sszb (手术主表)
- h15_ssxb (手术明细表)
- BQ_HLJL_NEW (护理记录,更新BRKS字段)
- bQ_xtjc (血糖记录,更新brks字段)

特殊处理:
- 根据参数获取材料科室ID(参数名: 'cl' + 转科科室ID)
- 更新fylbid='15'(材料类别)的记录到材料科室

#### zkjl ≠ '1' (只标记停止)
- 只更新h12_yzzb表
- 设置tzbz=1(停止标志)、tzsj=当前时间、tzrid=操作人ID

### 8. 清理数据
- 删除h11_jshztzd1表中该病人的结算提示记录

### 9. 养老系统处理(可配置)
- 根据系统参数"ylmbbz"(启用养老管理系统)判断
- 如果启用且gfbh不为空:
  - 更新dict_oldie表的zkksid(转科科室编号)
  - 更新yw_dcmx表的ks(科室)

## 注意事项

1. **转科是待确认状态**: 转科后病人状态为6(转科),需要目标科室确认后才能完成转科
2. **事务处理**: 整个转科过程在数据库事务中执行,保证数据一致性
3. **药品和项目校验**: 
   - 根据系统参数"zxyptx"决定是否检查未发药
   - 根据系统参数"zxxmtx"决定是否检查未执行项目
   - 如果检查失败会阻止转科,必须先处理完才能转科
4. **床位自动停止**: 如果病人有床位未停止,系统会自动停止
5. **未结账费用**: 系统会检查是否有未结账费用,但不会阻止转科(返回标识供前端提示)
6. **医嘱处理**: 根据配置可以选择直接将医嘱转到新科室,或者只标记停止由新科室重新开立
7. **养老系统**: 如果启用养老管理系统,会同步更新养老相关表
8. **参数配置重要性**: 必须正确配置科室ID和费用类别参数,否则校验功能无法正常工作

## 示例

### 请求示例

```json
{
  "zyid": "202401010001",
  "zkksid": "0201",
  "zksj": "2024-01-15 14:30:00",
  "ksid": "0101",
  "userid": "USER001",
  "gfbh": "GF20240001"
}
```

### 成功响应

```json
{
  "code": 0,
  "msg": "转科申请成功,等待目标科室确认！",
  "hasUnpaidFees": true
}
```

### 失败响应

```json
{
  "code": 41001,
  "message": "请输入要转的科室!"
}
```
