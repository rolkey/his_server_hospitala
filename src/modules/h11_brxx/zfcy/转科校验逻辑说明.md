# 转科前置校验逻辑说明

## 概述
在转科操作前,系统会根据配置参数对病人的药品发放和项目执行情况进行校验,确保转科前所有必要的医疗操作都已完成。

## 校验流程

### 1. 未发药检查 (checkUnDispensedMedicine)

**触发条件**: 系统参数 `13/zxyptx` = '1' (执行药品提醒)

#### 1.1 检查医嘱执行次数表 (h13_yzzxcs)

检查是否有未发药的药品医嘱:

```sql
SELECT ISNULL(COUNT(*), 0) as count 
FROM h13_yzzxcs 
INNER JOIN h12_yzxb ON h13_yzzxcs.yzxh = h12_yzxb.yzxh 
  AND h13_yzzxcs.yzlx = h12_yzxb.yzlx 
  AND h13_yzzxcs.zyid = h12_yzxb.zyid 
  AND h13_yzzxcs.mxxh = h12_yzxb.mxxh
WHERE ISNULL(h13_yzzxcs.fybz, 0) <> 1          -- 未发药
  AND (h12_yzxb.xmzl = 2 OR h12_yzxb.xmzl = 3) -- 西药或中药
  AND (h13_yzzxcs.zxcs - h13_yzzxcs.bzxcs) > 0 -- 有未执行次数
  AND h13_yzzxcs.jfyl > 0                       -- 计费用量大于0
  AND h13_yzzxcs.zyid = @zyid
  AND h13_yzzxcs.zkksid IN (西药科室, 草药科室, 中药科室, 材料科室, 其他科室, 制剂科室)
```

**字段说明**:
- `fybz`: 发药标志 (1=已发药, 0或NULL=未发药)
- `xmzl`: 项目种类 (1=项目, 2=西药, 3=中药)
- `zxcs`: 执行次数
- `bzxcs`: 不执行次数
- `jfyl`: 计费用量
- `zkksid`: 执行科室ID

#### 1.2 检查医嘱执行次数退费表 (h13_yzzxcs_tf)

检查退费药品是否已发药(退药):

```sql
SELECT ISNULL(COUNT(*), 0) as count 
FROM h13_yzzxcs_tf 
INNER JOIN h12_yzxb ON h13_yzzxcs_tf.yzxh = h12_yzxb.yzxh 
  AND h13_yzzxcs_tf.yzlx = h12_yzxb.yzlx 
  AND h13_yzzxcs_tf.zyid = h12_yzxb.zyid 
  AND h13_yzzxcs_tf.mxxh = h12_yzxb.mxxh
WHERE ISNULL(h13_yzzxcs_tf.fybz, 0) <> 1 
  AND (h12_yzxb.xmzl = 2 OR h12_yzxb.xmzl = 3)
  AND ABS(h13_yzzxcs_tf.zxcs - h13_yzzxcs_tf.bzxcs) > 0
  AND h13_yzzxcs_tf.jfyl > 0
  AND h13_yzzxcs_tf.zyid = @zyid
  AND h13_yzzxcs_tf.zkksid IN (西药科室, 草药科室, 中药科室, 材料科室, 其他科室, 制剂科室)
```

#### 1.3 检查手术医嘱未发药 (h15_ssxb)

检查手术相关药品是否已发药:

```sql
SELECT ISNULL(COUNT(*), 0) as count 
FROM h15_sszb 
INNER JOIN h15_ssxb ON h15_ssxb.zyid = h15_sszb.zyid 
  AND h15_ssxb.ssid = h15_sszb.ssid
INNER JOIN h11_brxx ON h15_sszb.zyid = h11_brxx.zyid
WHERE h15_sszb.zyid = @zyid
  AND ABS(h15_ssxb.jfyl) > 0                    -- 计费用量不为0
  AND ISNULL(h15_ssxb.tpbz, 0) = 0              -- 未退品
  AND ISNULL(h15_ssxb.tjbz, 0) = 1              -- 已提交
  AND h15_ssxb.xmzl IN (2, 3)                   -- 西药或中药
  AND h15_ssxb.zxksid IN (西药科室, 草药科室, 中药科室, 材料科室, 其他科室, 制剂科室, 手术材料科室, 精品科室, 护理科室)
```

**字段说明**:
- `tpbz`: 退品标志 (0=未退品, 1=已退品)
- `tjbz`: 提交标志 (0=未提交, 1=已提交)
- `zxksid`: 执行科室ID

**校验结果**: 如果任一检查发现未发药记录,抛出错误 `ERR_41005`

---

### 2. 未执行项目检查 (checkUnExecutedItems)

**触发条件**: 系统参数 `13/zxxmtx` = '1' (执行项目提醒)

检查是否有未执行或未收费的非药品项目:

```sql
SELECT COUNT(*) as count
FROM h13_yzzxcs
INNER JOIN h12_yzxb ON h13_yzzxcs.yzxh = h12_yzxb.yzxh 
  AND h13_yzzxcs.yzlx = h12_yzxb.yzlx 
  AND h13_yzzxcs.zyid = h12_yzxb.zyid 
  AND h13_yzzxcs.mxxh = h12_yzxb.mxxh
INNER JOIN h12_yzzb ON h12_yzzb.yzxh = h12_yzxb.yzxh 
  AND h12_yzzb.yzlx = h12_yzxb.yzlx 
  AND h12_yzzb.zyid = h12_yzxb.zyid
WHERE (ISNULL(h13_yzzxcs.sfbz, 0) <> 1 OR ISNULL(h13_yzzxcs.clbz, 0) <> 1) -- 未收费或未处理
  AND h12_yzxb.xmzl = 1                                                     -- 项目类型(非药品)
  AND (h13_yzzxcs.zxcs - h13_yzzxcs.bzxcs) > 0                             -- 有未执行次数
  AND h13_yzzxcs.jfyl <> 0                                                  -- 计费用量不为0
  AND h13_yzzxcs.xmdj > 0                                                   -- 项目单价大于0
  AND h13_yzzxcs.fylbid IN (护理, 病床, 西药, 其他, 中药, 麻醉, CT, 心电)  -- 费用类别
  AND h12_yzzb.zyid = @zyid
```

**字段说明**:
- `sfbz`: 收费标志 (1=已收费, 0或NULL=未收费)
- `clbz`: 处理标志 (1=已处理, 0或NULL=未处理)
- `xmzl`: 项目种类 (1=项目, 2=西药, 3=中药)
- `xmdj`: 项目单价
- `fylbid`: 费用类别ID

**校验结果**: 如果发现未执行项目,抛出错误 `ERR_41006`

## 涉及的数据表

| 表名 | 说明 | 用途 |
|------|------|------|
| h13_yzzxcs | 医嘱执行次数表 | 检查药品发放和项目执行情况 |
| h13_yzzxcs_tf | 医嘱执行次数退费表 | 检查退费药品是否已退药 |
| h12_yzxb | 医嘱明细表 | 获取医嘱项目类型等信息 |
| h12_yzzb | 医嘱主表 | 关联医嘱主记录 |
| h15_sszb | 手术主表 | 手术记录 |
| h15_ssxb | 手术明细表 | 检查手术药品发放情况 |
| h11_brxx | 病人信息表 | 关联病人基本信息 |

## 关键字段说明

### 项目种类 (xmzl)
- `1`: 项目(检查、治疗等非药品项目)
- `2`: 西药
- `3`: 中药

### 标志字段
- `fybz`: 发药标志 (0/NULL=未发药, 1=已发药)
- `sfbz`: 收费标志 (0/NULL=未收费, 1=已收费)
- `clbz`: 处理标志 (0/NULL=未处理, 1=已处理)
- `tpbz`: 退品标志 (0/NULL=未退品, 1=已退品)
- `tjbz`: 提交标志 (0/NULL=未提交, 1=已提交)

### 次数字段
- `zxcs`: 执行次数 (应执行的总次数)
- `bzxcs`: 不执行次数 (不需要执行的次数)
- 实际需执行次数 = `zxcs - bzxcs`

## 配置参数

### 开关参数
| 参数 | 说明 | 值 |
|------|------|-----|
| 13/zxyptx | 执行药品提醒 | 1=启用, 0=不启用 |
| 13/zxxmtx | 执行项目提醒 | 1=启用, 0=不启用 |

### 科室参数(用于药品检查)
- `13/xyksid`: 西药科室ID
- `13/cyksid`: 草药科室ID
- `13/zyksid`: 中药科室ID
- `13/clksid`: 材料科室ID
- `13/qtksid`: 其他科室ID
- `13/zjksid`: 制剂科室ID
- `13/ssclksid`: 手术材料科室ID
- `13/jpksid`: 精品科室ID
- `13/hlksid`: 护理科室ID

### 费用类别参数(用于项目检查)

| 参数代码 | 参数名称 | 说明 | 格式 |
|---------|---------|------|------|
| 40/hlfylbid | 化验费用类别 | 化验项目费用类别编号 | 单个或逗号分隔,如"08"或"08,09" |
| 40/bcfylbid | B超费用类别 | B超检查费用类别编号 | 单个或逗号分隔 |
| 40/xgfylbid | X光费用类别 | X光检查费用类别编号 | 单个或逗号分隔 |
| 40/qtfylbid | 其他费用类别 | 其他项目费用类别编号 | 单个或逗号分隔 |
| 40/mrfylbid | MR费用类别 | MR检查费用类别编号 | 单个或逗号分隔 |
| 40/zyfylbid | 中医费用类别 | 中医项目费用类别编号 | 单个或逗号分隔 |
| 40/ctfylbid | CT费用类别 | CT检查费用类别编号 | 单个或逗号分隔 |
| 40/xdfylbid | 心电费用类别 | 心电图费用类别编号 | 单个或逗号分隔 |
| 40/kffylbid | 康复费用类别 | 康复项目费用类别编号 | 单个或逗号分隔 |

**说明**: 
- 费用类别参数值支持逗号分隔多个ID,例如: "08,09,10"
- 系统会自动将逗号分隔的值拆分成数组进行匹配
- 所有费用类别会合并后统一检查

## 错误处理

| 错误码 | 错误信息 | 说明 |
|--------|---------|------|
| ERR_41005 | 该病人有未发药，请发药后，再办转科！ | 发现未发药的药品医嘱 |
| ERR_41006 | 该病人有项目未执行，请医技科室执行后，再办转科！ | 发现未执行的项目 |

## 业务逻辑说明

### 为什么要检查未发药?
1. **医疗安全**: 确保病人已获得应得的药品治疗
2. **费用完整性**: 避免转科后药品费用归属不清
3. **流程规范**: 保证医嘱执行的完整性

### 为什么要检查未执行项目?
1. **治疗完整性**: 确保检查、治疗等项目已完成
2. **费用结算**: 避免未执行项目影响费用结算
3. **科室责任**: 明确各科室的医疗责任

### 退费药品的特殊处理
- 退费药品(h13_yzzxcs_tf表)也需要检查是否已退药
- 使用`ABS()`函数处理退费数量(可能为负数)
- 确保退药流程完整

### 手术药品的特殊处理
- 手术药品单独检查(h15_ssxb表)
- 只检查已提交(tjbz=1)且未退品(tpbz=0)的记录
- 涉及更多科室(手术材料、精品、护理等)

## 注意事项

1. **参数配置**: 必须正确配置所有相关参数,否则校验可能失效
2. **性能考虑**: 检查涉及多表关联,数据量大时可能影响性能
3. **业务灵活性**: 可通过参数开关控制是否启用校验
4. **异常处理**: 校验失败会阻止转科操作,需要先处理完问题
5. **科室范围**: 只检查特定科室范围的药品和项目,避免误判

## 使用示例

### 场景1: 启用所有校验
```typescript
// 系统参数配置
13/zxyptx = '1'  // 启用药品提醒
13/zxxmtx = '1'  // 启用项目提醒

// 转科时会进行完整校验
// 如果有未发药或未执行项目,会抛出异常
```

### 场景2: 只启用药品校验
```typescript
// 系统参数配置
13/zxyptx = '1'  // 启用药品提醒
13/zxxmtx = '0'  // 不启用项目提醒

// 转科时只检查药品发放情况
// 不检查项目执行情况
```

### 场景3: 不启用校验
```typescript
// 系统参数配置
13/zxyptx = '0'  // 不启用药品提醒
13/zxxmtx = '0'  // 不启用项目提醒

// 转科时不进行药品和项目校验
// 直接进入后续流程
```

## 测试要点

1. **正常流程**: 所有药品已发放,所有项目已执行,转科成功
2. **未发药**: 有未发药记录,转科失败,提示ERR_41005
3. **未执行项目**: 有未执行项目,转科失败,提示ERR_41006
4. **退费药品**: 有未退药记录,转科失败
5. **手术药品**: 手术药品未发放,转科失败
6. **参数关闭**: 参数为'0'时,跳过校验,转科成功
7. **边界情况**: 执行次数为0、单价为0等边界情况
